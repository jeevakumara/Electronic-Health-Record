Clinical Motivation

The Medical Audit Dilemma in Healthcare Systems

Why traditional database update models fail in patient healthcare records.

The Mutation Dilemma

  • SQL UPDATE statements permanently overwrite old values.
  • Dosage revisions destroy the historical clinical record.
  • Adverse Drug Event (ADE) investigations cannot determine prior states.
  • Vulnerable to intentional or accidental doctor tampering.

Regulatory Imperatives

  • HIPAA § 164.312(b): Enforces immutable hardware/software audit controls.
  • FDA 21 CFR Part 11: Computer-generated, time-stamped audit trails.
  • GDPR Article 30: Explicit records of data processing activities.
  • Solution: Native SQL:2011 temporal system versioning.

System Architecture

3-Tier Architecture & End-to-End Data Flow

Secure, decoupled architecture bridging client requests and the database engine.

1. Client Tier (Frontend)

  • Interactive medical dashboard, registration & updates.
  • Form input validation before network transmission.
  • Temporal date-time picker for time-travel queries.

2. Server Middleware Tier (Express.js)

  • Authorized security middleman (Zero direct DB access).
  • Connection pool to MariaDB with auto-reconnection.
  • Constructs dynamic temporal queries (AS OF & ALL).

3. Database Tier (MariaDB 11.4 Engine)

Stores current active rows in primary tables; automatically intercepts mutations and routes superseded records into hidden historical partitions with microsecond precision timestamps.

Database Engineering

Schema Design with System Versioning

Implemented in database/schema.sql using WITH SYSTEM VERSIONING.

CREATE TABLE patients (
    patient_id INT AUTO_INCREMENT PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    age INT, contact_number VARCHAR(15), emergency_details TEXT
) WITH SYSTEM VERSIONING;

CREATE TABLE prescriptions (
    prescription_id INT AUTO_INCREMENT PRIMARY KEY,
    patient_id INT, doctor_id INT,
    diagnosis VARCHAR(255) NOT NULL, medication VARCHAR(255) NOT NULL, dosage VARCHAR(100) NOT NULL,
    FOREIGN KEY (patient_id) REFERENCES patients(patient_id) ON DELETE CASCADE,
    FOREIGN KEY (doctor_id) REFERENCES doctors(doctor_id) ON DELETE CASCADE
) WITH SYSTEM VERSIONING;

The Hidden Mechanics:

MariaDB creates invisible system columns ROW_START and ROW_END. An update atomically closes ROW_END on the previous tuple and inserts the revision with ROW_START = current_timestamp.

Temporal Queries

Time-Travel Query Processing (AS OF & ALL)

1. Point-in-Time Reconstruction

SELECT p.*, pt.full_name, d.full_name
FROM prescriptions 
  FOR SYSTEM_TIME AS OF TIMESTAMP(?) p
LEFT JOIN patients FOR SYSTEM_TIME AS OF ...
WHERE p.prescription_id = ?;

Reconstructs exact medical regimen at any past moment.

2. Full Audit Timeline

SELECT prescription_id, diagnosis, 
       medication, dosage, 
       ROW_START, ROW_END
FROM prescriptions FOR SYSTEM_TIME ALL
WHERE prescription_id = ?
ORDER BY ROW_START DESC;

Extracts entire revision sequence across partitions.
